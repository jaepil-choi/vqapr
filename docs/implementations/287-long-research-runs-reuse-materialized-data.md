## 왜 필요한가

실제 자료 시험에서 여러 전략이 공통 팩터를 각자 다시 계산하면 순차 실행 시간과 병렬 실행
메모리가 모두 늘었다. 반면 공통 계산을 DataModel로 한 번 저장한 뒤 여러 전략이 읽으면 같은
결과를 더 적은 반복 작업으로 만들었다.

처음 사용하는 사람은 DataModel과 StrategyModel의 역할은 알더라도 장시간 연구를 어떤 순서로
실행하고 병렬 작업 수를 어떻게 정해야 하는지 놓칠 수 있다. 엔진 기능은 이미 있었지만 공개
안내에 성능상 중요한 실행 순서를 한곳에 모을 필요가 있었다.

## 무엇이 바뀌었는가

- 여러 전략이 공유하는 결합·과거 구간 계산·순위·예측은 DataModel에서 한 번 만들도록 안내함
- DataModel 실행이 끝난 뒤 결과 자료를 확인하고 소비 전략을 실행하도록 안내함
- 전략 한 개의 시간과 최대 메모리를 먼저 본 뒤 병렬 작업 수를 정하도록 안내함
- 순차 실행과 병렬 실행을 모두 비교하고 결과 내용도 함께 확인하도록 안내함
- 전략에는 전략별 점수와 자본 배분만 남기도록 경계를 분명히 함

## 바꾸지 않은 것

- CLI와 Python 공개 계약
- DataModel과 전략의 실행 방식
- 기존 스캐폴드와 등록 형식
- 병렬 실행의 프로세스 격리와 자료 고정 규칙

## 검증 방법

- 현재 소스의 문서·스킬 검사를 실행함

- 저장소 소스 경로를 가져오지 않은 설치 환경에서 진행함

- 내보내기는 자산, 보유 종목, 체결, 목표 비중, 자체 기록, 보고서 파일을 생성함
